# RealityGlitch · 现实入侵

把桌上任意一件真实物品变成被入侵的游戏关卡,玩家用手势把它封印。

摄像头对准桌面,AI 识别每件物品并给它一个入侵身份、一种打法;红色光圈贴在真实物品上并跟着它移动;玩家不用鼠标,手放在物品上做手势推动游戏。

> 黑客松原型。游戏逻辑、手势识别、物品跟踪都在本机运行;只有玩家点击"扫描"时,才会把一帧画面发给模型。

## 它做了什么

1. **扫描桌面**:点一下,AI 找出桌上 1 到 4 件物品,给每件起一个入侵身份、一个弱点手势和一种打法。换一张桌子,关卡完全不同。
2. **入侵点贴在真实物品上**:取景框和强度条锚定在物品上。移动物品或相机,框会跟着走;被手挡住时保持最后位置,并显示"信号丢失"。
3. **手就是控制器**:摄像头实时识别手势,手放在哪件物品上,就作用在哪件物品上。
4. **每件物品打法不同**:模型只能从固定名单里挑,规则由程序执行。

| 打法 | 怎么打 |
|---|---|
| 护盾 | 握拳打不动,要先用张开手掌连击 3 次打碎护盾 |
| 蓄力 | 单拳只能擦伤,连续出拳蓄满才爆发,停手会漏掉蓄力 |
| 相位 | 大部分时间打不到,窗口周期性打开约 1.7 秒 |
| 连击 | 限时内连续命中 3 次,断了会回血 |
| 普通 | 直接打 |

5. **手机当摄像头**:手机和电脑连同一个热点,扫码配对,画面经 WebRTC 直传电脑;电脑上可以调倍率、切广角。

## 怎么玩

| 手势 | 作用 |
|---|---|
| 张开手掌 | 防御入侵波;对着护盾型物品则是击碎护盾 |
| 握拳(手放在物品上) | 攻击该物品,并积累技能能量 |
| V 手势(手放在物品上) | 能量满 100 时释放封印,可穿透护盾和相位 |

没有摄像头也能玩:键盘 `1` 张开手掌、`2` 握拳、`3` V 手势,`空格` 开始,`R` 重来。键盘模式会自动瞄准当前能打的物品。

**胜负由程序判定**:把所有入侵点封印即胜;现实稳定度归零或倒计时结束即败。

## 运行

### 环境

- Windows 10/11,Chrome 或 Edge
- Node.js 20+
- Python 3.11+
- 一个摄像头(电脑摄像头、Iriun Webcam 等虚拟摄像头,或手机直连)

### 获取代码

```bash
git clone https://github.com/nineteem526/RealityGlitch.git
cd RealityGlitch
```

### 一键启动

双击根目录的 **`start.bat`**。它会:

1. 检查 Python,缺依赖时自动 `pip install -r server\requirements.txt`;
2. 没有 `server\.env` 时从模板复制一份;
3. 另开一个窗口启动后端(`127.0.0.1:8011`);
4. 安装前端依赖并启动前端,浏览器自动打开 **https://localhost:5173**。

第一次打开浏览器会提示"不安全",这是本地自签证书,点"高级"再"继续访问"。

### 配置模型(可选)

不配置也能完整玩一局(用预设关卡,界面标注"预设数据(离线)")。要启用 AI 生成:

1. 打开 `server\.env`;
2. 填入 `LLM_API_KEY`;
3. 按需修改 `LLM_BASE_URL` 和 `LLM_MODEL`(任何 OpenAI 兼容的 `/chat/completions` 接口都可以);
4. 模型不支持图片输入时设 `LLM_VISION=false`,界面改用"手动输入物品名"。

`server\.env` 已被 `.gitignore` 排除,**不要提交**。

### 手机直连(可选)

1. 电脑开启 Windows 移动热点,手机连上它;
2. 在页面右上角点"手机直连",右下角出现二维码和 6 位配对码;
3. 手机扫码,第一次点"继续访问",输入配对码,选后置摄像头;
4. 画面接入后,电脑底部出现倍率和镜头控制条。

连不上时回退到普通摄像头即可,游戏不依赖这条链路。

### 测试与构建

```bash
cd app && npm test          # 前端 84 个测试
cd app && npx tsc -b        # 类型检查
cd server && python -m unittest discover -s tests   # 后端 21 个测试
```

## 设计原则

- **AI 只生成内容,不决定胜负。** 模型只能填受限字段(物品名、故事、手势、打法、时长、难度、颜色),不执行任何模型返回的代码;伤害、倒计时、胜负全部由程序判定。
- **严格校验,两道关。** 后端用 pydantic 校验一次(范围、长度、枚举、禁止标记字符、多余字段一律拒绝),前端再校验一次。打法名不在名单里会被拒绝,不会悄悄降级。
- **不连模型也能玩。** 模型失败、超时、未配置,都会回退到预设关卡并在界面标注。
- **视频留在本机。** 手势识别和物品跟踪都在浏览器里运行,模型文件本地加载;只有点击"扫描"时才发送单帧图片。
- **来源如实标注。** 预设数据、AI 生成、手动输入三种来源在界面上明确显示。
- **密钥只在后端。** API Key 只存在 `server/.env`,前端拿不到。
- **局域网最小暴露。** 手机经前端代理访问后端,后端只绑定 `127.0.0.1`;对非本机来源只开放"配对"一个接口,不能调用生成接口,拿不到 Key。配对码 6 位,错误次数过多会被限流。

## 架构

```
手机 / 摄像头 ──► <video> ──► MediaPipe 手势识别 ─┐
                      │                            ├─► 稳定器(置信度 / 持续时间 / 冷却)
                      ├─► 模板匹配跟踪(物品位置) ─┘            │
                      │                                         ▼
                      └─► 点击扫描时取一帧 ──► FastAPI ──► 模型 ──► Schema 校验 ──► Level
                                                                         │
            Canvas 叠加层(取景框 / 打法标记 / 手部准星 / 碎裂) ◄── 纯 reducer 状态机(规则全在这里)
```

```
app/      React + TypeScript + Vite 前端
  src/game/    状态机(engine)、打法(traits)、校验(api)、几何(rifts)、预设关卡
  src/vision/  摄像头、手势识别、稳定器、物品跟踪
  src/link/    手机直连:信令、WebRTC、配对面板、镜头控制
  src/ui/      Canvas 叠加层、红色渗透效果
server/   FastAPI 后端:模型调用、Schema 校验、配对信令
gesture-check/  最初的 MediaPipe 验证页,仅供参考
```

## 已知局限

写在这里,不让人以为它比实际更完整。

- **扫描需要等待**:一次扫描通常 7 到 20 秒,取决于模型。
- **物品名偶尔认错**:例如把书识别成盒子。不影响玩法,但名字可能不准。
- **跟踪是简单模板匹配**:物品被长时间遮挡、大幅旋转或光线剧变时会丢失,丢失后会提示并尝试在整个画面重新找回。
- **只测过有限设备**:手机直连、广角切换、倍率控制依赖手机浏览器暴露的能力;iPhone 的 Safari 通常不开放变焦。手机端到电脑的 WebRTC 连通性受热点和网络环境影响。
- **手势依赖光线和距离**:手太小或太暗时识别会掉,识别面板里有灵敏度可调。
- **数值手感未充分调校**:蓄力速度、相位窗口时长、连击时限等见 `app/src/game/traits.ts`。
- **没有接入机器人**:机器人联动(`RobotAdapter`)只在设计里,未实现。
- **仅在 Windows 上开发和测试**。
